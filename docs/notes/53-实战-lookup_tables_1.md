# 53 · 实战 · `lookup_tables_1`（7 段 if/else 分支链 → 查表）

> **TMA 一级**：**Bad_Speculation**（本系列唯一）· **优化技术**：**查找表替代数据相关分支链**·**加速比**：**1.91x 本机** ≈ 1.87x 文档

---

## 一、读题（Step 0）

**任务**：1M 个 `v ∈ [0, 100]` 的整数做 8 桶直方图分桶。分桶边界是硬编码阈值。

**基线**（7 段 if/else 链）：
```cpp
if (v <= 12) return 0;
if (v <= 28) return 1;
if (v <= 40) return 2;
if (v <= 52) return 3;
if (v <= 70) return 4;
if (v <= 82) return 5;
if (v <= 99) return 6;
return DEFAULT_BUCKET;
```

**优化**（100 元素查表）：
```cpp
static const int buckets[100] = {0,0,...,1,1,...,2,2,...,6,6,...};
return buckets[v];   // 一条 mov 完成, 零分支
```

**基线切换**：把 `mapToBucket` 换回 if/else 即可（本文档 § 一 已给完整代码）。

## 二、Step ①②③④ 本机实测

| | 基线 if/else 链 | 优化 查表 | 变化 |
|--|---------------|----------|------|
| **Google Bench** | **4122 μs** | **2162 μs** | **1.91x** ✅ |
| 每 iter instructions | 37.9 M | **11.4 M** | **↓ 3.3x** |
| 每 iter cycles | 37.4 M | 15.9 M | ↓ 2.35x |
| IPC | 1.01 | 0.71 | 都低（本实验就是 mispredict 地狱）|
| 每 iter **branch-miss** | **1.11 M** 🤯 | 513 K | ↓ 2.16x |

## 三、🎯 为什么查表赢？三层拆解

### 1. 数据相关分支 = 分支预测器的噩梦

`v ∈ [0,100]` **随机分布** → 每个 `v` 落在 8 个桶的概率大致均匀。分支预测器面对一条有 8 种结果的分支，**猜错率极高**（哪怕最好的ITTAGE predictor，对随机分支也只能追平 coin flip）。

**每 iter 1.11M 次分支失败**：1M+ 元素 × 平均每元素 1+ 次误判 = 直方图分桶本身就"每元素至少 mispredict 一次"。每次误判代价 15-30 周期 → 光误判就吃掉 ~17-33M cycles/iter。

### 2. 查表：**分支密度归零，指令数砍 3.3x**

`buckets[v]` = 一条 `mov eax, [table + rax*4]`：
- **无条件跳转**（v 直接索引）→ **零分支误判**
- **一条指令**替代 7 条 if + cmp + jump 链 → 指令数 ↓3.3x
- 表 400B 常驻 L1 → 无 cache 代价（本实验 cache-miss 只 3K/iter）

### 3. 但优化版仍有 513K branch-miss/iter —— 来自哪？

**主循环 `for (auto v : values)` 的迭代终止判断**——每 1M 次迭代都有 loop-back 分支。虽然通常高度可预测（100万次都 taken、最后一次 not-taken），但现代 CPU 的循环溢出检测（loop streamer）不完美时也会 mispredict。这部分**基线也付**，不是差异源。

## 四、"查表 vs 分支链"适用条件

**适合查表**：
- 输入值域小且连续（`v < 256` 甚至 `< 65536`，能塞进 L1/L2）
- 输出是**简单值**（不是复杂逻辑）
- 分支链**长度 ≥ 3** 且**输入不可预测**
- 频繁调用，热循环

**不适合**：
- 值域巨大（`uint64`）→ 表爆炸
- 计算比查表还便宜（如 `v/2` 一条 shift）
- 分支高度可预测（如 `if (v > 1e9)` 实际永远 false）

**通用形式**：**"以空间换分支"**——本质上是消除 **Bad Speculation** 那一类。

## 五、Bad_Speculation 药箱的完整视角

对照第 3 课 TMA 药箱表：

| 药方 | 场景 | 本系列实证 |
|------|------|-----------|
| **查表替代分支链**（本实验） | 阈值/映射类分支 | **53 号 1.91x** |
| **平衡判断树** | 分支不可去但可减深度 | 5-11 讲过 |
| **`? :` 选择指令 / if-conversion** | 单表达式分支 | 5 号语句级优化 |
| **分支合并 / 条件编译** | 静态可判的分支 | 5 号 |
| **`__builtin_expect` / `[[likely]]`** | 无法去但能提示预测器 | C++20 语法 |

**Bad_Speculation 单独看只有一个实验（53 号）**——但**跨类的 mispredict** 到处都是（本系列 50 号找 `\n`、52 号 qsort 间接调用、40 号 warmup 会看到算法选择消除分支）——它是**隐形跨类杀手**。

## 七、一句话收口

> **数据相关的随机分支 = CPU 流水线的定时炸弹**——1M 元素 × 每元素 1 次 mispredict × 每次 20 周期 = 每 iter 20M 周期纯烧在流水线清空上。查表把它压到 0 分支——**"用空间换分支"是 Bad_Speculation 最锋利的对症药**。1.91x 看起来温和，但 IPC 只有 1 意味着基线**每周期只完成 1 条指令**（大核能到 4-6），优化后 IPC 依然低（主循环 overhead 占大头）——**这就是"消除 mispredict 后立刻撞到下一层瓶颈"的经典案例**。

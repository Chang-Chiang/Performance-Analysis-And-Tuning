# 02 · 性能分析工具

> **立意**：知道"慢"还不够，得**定位到函数/代码行/硬件资源**。工具再多，原理只有 6 类——记住这张表，任何新工具你都能秒归类。

---

## 一、理论主干

### 1. 六大类工具（**开销 ↔ 细节 权衡**）

| 类别 | 原理 | 开销 | 代表工具 | 用于 |
|------|------|------|---------|------|
| **计数器** | 装个"里程表"数事件发生几次 | 低 | `perf stat`、VTune | 宏观体检：IPC / cache-miss |
| **采样** | 定时中断抓拍程序在哪 | 中 | `perf record`、VTune Hotspots | 找热点函数/行 |
| **追踪** | 事件按时间顺序全程录像 | 高 | `strace`、`perf trace`、`ftrace` | 时序/系统调用分析 |
| **插桩** | 往代码里插探针采集极细信息 | 最高 | `Valgrind`、`Advisor` | 深挖内存错误/向量化 |
| **模拟** | 不真跑，用软件模拟硬件 | — | `gem5`、`Sniper` | 科研/教学 |
| **静态** | 不运行只读代码 | 零 | 编译器报告、`LLVM opt` | 早期预判 |

> 📌 **黄金律**：**开销与信息细节成正比**。实战**永远从最便宜的 `perf stat` + `perf record` 起步**，挖不动了才上插桩。

### 2. `perf` — Linux 随身医生（**先掌握它**）

Linux 内核自带、免费、开销低。四个子命令覆盖 90% 需求：

| 子命令 | 干什么 | 关键指标 |
|--------|--------|---------|
| `perf stat` | 事件计数 | **IPC**、**cache-miss rate** |
| `perf record` + `perf report` | 采样→交互式看热点 | 最耗时函数占比 |
| `perf top` | 实时热点 | 系统级观察 |
| `perf trace` | 系统调用追踪 | I/O 密集分析 |
| `perf c2c` | 缓存行争用 | **伪共享诊断** |

**IPC 直觉（第 1 课 Roofline 的落地指标）**：
- 现代大核每周期可发射 4~6 条指令 → IPC 上限 ≈ 4-6
- **IPC 0.5~1** → CPU 大片空转（多半等内存）
- **IPC 4+** → 后端喂得满满的

**火焰图**（`perf record` 的可视化）：
```bash
perf record -F 99 -g ./app
perf script | stackcollapse-perf.pl | flamegraph.pl > flame.svg
```
- **宽度** = 耗时占比 → 找**最宽的平顶**（真热点）
- **高度** = 调用栈深度
- **颜色** = 无意义

### 3. `Intel VTune Profiler` — 全科 CT 机

`perf` 的豪华官方版，把分析打包成预设采集项：

| 采集项 | 干什么 |
|--------|--------|
| **Hotspots** | 定位最耗时函数/代码行（GUI 版 perf record） |
| **Microarchitecture Exploration** | 底层跑 **TMA**，直接告诉你 Memory/Core Bound |
| **Memory Access** | 带宽 / NUMA / cache miss |
| **Threading** | 线程并行度、锁竞争、负载均衡 |
| **HPC Perf Characterization** | 浮点效率、向量化率 |
| **GPU Offload / GPU Compute** | Intel GPU |

```bash
vtune -collect hotspots -result-dir ./res ./app
vtune -report hotspots  -result-dir ./res
vtune-gui               # GUI 打开
```

**perf vs VTune 怎么选**：命令行/快速/免费/SSH 远程 → `perf`；要图形、要 TMA 分析树、要深挖内存/线程 → `VTune`。**采样原理相同**。

### 4. `Intel Advisor` — 向量化 & Roofline 专科

| 采集 | 用途 |
|------|------|
| **Survey** | 扫循环/函数，看向量化状态与时间占比 |
| **Trip Counts** | 迭代次数 |
| **Dependencies** | 数据依赖 → 能否安全向量化 |
| **Vectorization** | 向量化建议 + 预估收益 |
| **Roofline** | 把第 1 课的 Roofline 模型**真画出来** |

```bash
advixe-cl --collect survey     --project-dir ./proj -- ./app
advixe-cl --collect dependencies --project-dir ./proj -- ./app
```

详见 [`docs/intel_advisor.md`](../theory/intel_advisor.md)（含 `loop_interchange_1` 优化前后完整对比）。

### 5. 其他常用

- **gprof**：编译加 `-pg`，函数级调用图。跨平台、精度有限。
- **Valgrind**：
  - `--tool=memcheck` 查内存越界/泄漏（**调试神器**）
  - `--tool=cachegrind` 模拟 cache 行为
  - `--tool=massif` 堆分析
  - ⚠️ 慢 10~50x，别拿它做性能剖析。
- **strace / ltrace**：追系统/库调用。`strace -c ./app` 看谁在疯狂 syscall（对应 `real ≫ user+sys`）。
- **ftrace / trace-cmd**：内核函数追踪（低开销）。

## 二、关键命令速查

```bash
# 一句话体检
perf stat ./app
perf stat -e cache-misses,cache-references,instructions,cycles ./app
perf stat -d ./app                 # 详细

# 采样定位热点
perf record -g ./app               # -g 连调用栈
perf report                        # 交互看
perf report --stdio                # 文本

# 实时热点
sudo perf top -p <pid>

# 系统调用
perf trace -e read,write ./app
strace -c ./app

# 伪共享专项
perf c2c record ./app && perf c2c report

# 火焰图
perf record -F 99 -g ./app && perf script | stackcollapse-perf.pl | flamegraph.pl > flame.svg

# VTune
vtune -collect hotspots        -result-dir ./res ./app
vtune -collect uarch-exploration -result-dir ./res ./app   # TMA 树

# Advisor
advixe-cl --collect survey       --project-dir ./proj -- ./app
advixe-cl --collect tripcounts   --project-dir ./proj -- ./app
advixe-cl --collect dependencies --project-dir ./proj -- ./app
```

## 三、决策链路：从怀疑慢到定位瓶颈

```
怀疑程序慢
   ↓ ① time 定 CPU/IO 类型 (第 1 课)
   ↓ ② perf stat 看 IPC & cache-miss (快速分诊)
        IPC 低 + miss 高   → Memory Bound
        IPC 尚可但周期堵    → Core Bound
   ↓ ③ perf record + 火焰图 → 揪出热点函数/行
   ↓ ④ VTune Microarch / Advisor Roofline → 深挖微架构 / 向量化
   ↓ ⑤ 特殊症状:
        伪共享 → perf c2c
        I/O 密 → strace
        内存错 → valgrind memcheck
```

**多角度交叉验证**是本课的元教训：单看 `-Rpass` 会说"AoS 也向量化了没问题"，perf 会揭穿它是带宽瓶颈（详见 `06/08`）。

## 四、一句话收口

> **实战从最便宜的 `perf stat` + `perf record` 起步**；需要图形化 / TMA 分析树 → VTune；需要向量化建议 & Roofline → Advisor。**别一上来就 `valgrind`**——开销会把你的耐心也 profile 掉。

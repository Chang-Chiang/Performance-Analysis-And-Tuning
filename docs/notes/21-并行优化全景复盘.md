# 21 · 并行优化全景复盘（第 8–11 课串联）

> **目的**：把 OpenMP / TBB（共享内存多核，线程 vs 任务）、CUDA（GPU 高吞吐）、MPI（分布式集群）**缝成一张图**。以后拿到并行任务，脑子自动浮现"**先问哪三个问题、查哪个瓶颈、开哪箱药**。

---

## 一、思维跃迁：单核 → 并行（不变的闭环 + 新敌人）

```
第 3 阶 单核：把一个厨师榨到极致 ─┐
                                 ├─► 第 4 阶 并行：同时用更多"计算单元"
                                 │    OpenMP=同厨房多厨师(共享内存/线程)
                                 │    TBB   =同一厨房但"任务随取随派"(共享内存/工作窃取)
                                 │    CUDA  =上千学徒流水线(GPU/显存)
                                 │    MPI   =多楼层独立厨房靠传菜窗口(分布式/进程)

闭环不变(20 号文档):
 ① 度量基线 → ② 热点 → ③ TMA/分诊 → ④ 开药 → ⑤ 验证
但多了一个全新维度:
 ⑥ 协调开销: fork-join / 同步 / 通信 / 数据搬运
```

**核心升级**：单核只跟"**延迟+带宽**"斗；并行多了一个敌人——**协调开销**。**并行优化的本质 = 用"并行收益"付"协调开销"账单，别让账单吃掉利润。**

## 二、⭐ 并行三问：任何并行任务的起手式

| 三问 | OpenMP | TBB | CUDA | MPI |
|------|--------|-----|------|-----|
| **① 怎么切**（数据/任务划分）| 并行**最外层循环**；`collapse` 合维 | `parallel_for`+`blocked_range` 递归对分 | grid/block/**二维 32×32** 布局铺满 SM | 行/列/**棋盘 Cannon** 划分 |
| **② 怎么合**（通信/同步）| `shared/private/reduction`；`barrier`/`nowait` | 闭包捕获天然作用域；`parallel_reduce` 归约 | warp 内 `__syncwarp`、块内 `__syncthreads` | Send/Recv、Bcast/Scatter/Gather/Reduce、`Sendrecv` 防死锁 |
| **③ 均不均**（负载均衡）| `schedule` static/dynamic/guided | 默认 `auto` **工作窃取** + 分区器 | 布局整齐避免 warp 空转 | 按块 vs 交叉（**交叉反而比串行慢**！）|

> 三问答完，方案基本定型。**大多数"并行不提速"都能回溯到某一问答错了。**

## 三、⭐ 跨四模型的 4 条共同母题（最高价值·可迁移）

几种技术虽硬件迥异，**病因和药方惊人地重复**。看懂"同构"，你就融会贯通：

### 母题 ① 掩盖延迟：让"取数/通信"和"计算"重叠
```
OpenMP:  nowait 让先干完的线程别干等
TBB:     parallel_pipeline / flow_graph 让不同 item 的不同阶段重叠(藏阶段延迟)
CUDA:    双缓冲共享内存预取, 算 K 时取 K+1 (藏 400~800 周期显存延迟)
MPI:     非阻塞 Isend/Irecv + 双缓冲, 算当前块时后台传下一块 (藏网络延迟)
```
> 👉 **同一个"乒乓双缓冲"思想**，从 GPU 显存一路用到集群网络。

### 母题 ② 局部性：把数据放对位置，让访问连续
```
07 课:   循环交换/分块、AoS→SoA (沿缓存行连续走)
TBB:     affinity_partitioner 复用"块↔线程"绑定(缓存/NUMA 局部性)
CUDA:    合并访存 (32 线程连续) + 共享内存 tiling
MPI:     棋盘划分 (只跟邻居通信) + NUMA first-touch
```
> 👉 **本质都是第 1 课 Roofline 的"提高算术强度"**：每搬一次数据，尽量多算几回。

### 母题 ③ 争用同一资源 → 打乱并行（四模型各版的"伪共享"）
```
OpenMP:  伪共享 (多线程写同一 64B 缓存行) → alignas64 / reduction
TBB:     同伪共享 → cache_aligned_allocator / parallel_reduce; 真共享→并发容器
CUDA:    warp 分化 (同束 32 线程走不同分支串行) + bank 冲突 (挤同一共享内存组)
MPI:     集合通信 / Barrier 全局同步 (所有进程干等最慢的)
```
> 👉 全是"**本该并行的单元被迫串行**"这一类病，只是发生在缓存行/warp/进程三个不同粒度。**治法也同构**：让各单元用独立资源 / 减少被迫同步。

### 母题 ④ 减协调开销：少切换、少同步、合消息
```
OpenMP:  并行区扩张/合并 (fork-join 从 N 次 → 1 次)
TBB:     任务框架默认摊薄 fork-join; 归约交 parallel_reduce 少同步
CUDA:    展开消分支、合理线程数
MPI:     合并小消息 (α + β·n, 少付 α)、减 Barrier
```

## 四、并行收益天花板：Amdahl vs Gustafson 的实战落点

```
              强扩展 (规模固定, 加算力)         弱扩展 (规模随算力同增)
                 = Amdahl 定律                    = Gustafson 定律
OpenMP 单机多核  ★最贴合 (串行部分是硬顶)         一般
TBB    单机多核  ★同样撞 Amdahl (与 OpenMP 同一天花板) 一般
CUDA   GPU 数据并行  适合 (天然大规模)             适合
MPI    跨节点集群     撞通信墙                     ★最贴合 (超算主战场)
```

三句话：**单机并行看 Amdahl（别指望线性加速）、超算靠 Gustafson 摊大饼、通信是分布式独有的新天花板**。

## 五、并行程序怎么"定位瓶颈"（诊断工具箱）

| 症状 | 用哪个工具/指标 | 对应药方 |
|------|----------------|---------|
| CPU 某核忙其余闲 / 利用率低 | VTune **Threading**、CPU 利用率直方图 | 负载均衡、并行区扩张 |
| 线程大量阻塞等待 | VTune Threading 的**等待/同步**视图 | `nowait`、减 `barrier` |
| GPU 吞吐低但线程全开 | Nsight：内存吞吐量、warp 活跃度 | 合并访存、消 warp 分化、算 4×4 块 |
| MPI 加速比不随节点涨 | **MPIP / Score-P** 看通信占比 | 合消息、Cannon、非阻塞重叠 |
| 多核反而更慢 (共享写) | **`perf c2c`** 查缓存行争用 | `alignas(64)`、`reduction` |

```
拿到一个程序 → 先 TMA/度量分诊:
 ├─ 单核就慢(还没并行)  ──► 20 号文档"两大药箱":
 │                            算法 > 布局 > 局部性 > 向量化 > 编译开关
 └─ 要并行 / 已并行:
      ├─ 单机多核         ──► 08 OpenMP: parallel for + reduction + schedule
      │                       + nowait + alignas + 并行区扩张

      └─ 跨节点           ──► 10 MPI: 合理划分(Cannon) + 非阻塞重叠
                              + 负载均衡 + 冗余换通信 + 防死锁
```

## 七、本机实测的四个并行实验（把抽象论点变成曲线）

| # | 模型 | 实测内容 | 关键数字 | 位置 |
|---|------|---------|---------|-----|
| ⑥ | OpenMP | 伪共享 + 测量纪律修正 | 反直觉→绑核放大→稳定 | `08 § 五` |
| ⑦ | OpenMP | 线程扫描 1→24 | 卡 ~12x（物理核 + HT + 带宽）| `08 § 五` |
| **⑨** | **CUDA** | **1D→2D→Shared tiling** | **1.22→0.71→0.55 ms，2.21x** | `09 § 七` |
| **⑩** | **MPI** | **加速比 + α+β·n 通信成本** | **8 rank 6.89x；合并小消息快 4~5x** | `10 § 九` |

**跨四个实验共同印证的三件事**：
1. **Amdahl 天花板无处不在**：⑦ OpenMP 卡 ~12x；⑩ MPI 单机近线性但 α 项随 size 增长；⑨ CUDA 布局改了才提得上去——**并行不是免费午餐**，每一层都有新瓶颈。
2. **数据/消息摆对位置 > 堆算力**：⑨ 从 1D→2D 一行不改算法 1.73x；⑩ 从 8×1KB→1×8KB 同样 8MB 快 4~5x——**都是母题 ② 局部性**在不同尺度上的化身。
3. **测量纪律决定数据可信度**：⑥ 一次翻车、⑩ 一次踩坑（Gather 缓冲区重叠 / Send 缓冲吃掉 α）——**每次都是「先怀疑测量，再怀疑计算机」**救回来的（详见 `30` 手册）。

## 八、复盘收口（三句话）

1. **并行三问**定方案：**怎么切 / 怎么合 / 均不均**；答错任一问 → 加速比打折甚至负收益。
2. **四大母题跨模型通用**：掩盖延迟、局部性、消争用、减协调——本质是"并行收益 vs 协调开销"的博弈。
3. **天花板理论**：单核看 Amdahl/Roofline，并行看通信与同步；**并行绝不是免费午餐**。

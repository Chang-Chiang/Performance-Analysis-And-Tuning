# 01 · 性能度量指标

> **立意**：优化前必须先能回答"现在多慢？目标多快？改完有没有变快？"。**没有度量，一切优化都是玄学。**
> 本篇是**全体系的量纲基础**，后面所有加速比数字都从这里定义。

---

## 一、理论主干

### 1. 三种时间（`time ./a.out` 给的三个数）

| 时间 | 含义 | 类比（餐厅点菜） |
|------|------|----------------|
| **real** | 墙上时钟时间（用户体感） | 从下单到上桌 |
| **user** | 用户态 CPU 时间（**你代码的消耗**） | 厨师真炒的时间 |
| **sys**  | 内核态 CPU 时间（系统调用） | 领食材、登记排队 |

**判断瓶颈类型（本课最重要的直觉）**：

```
real ≈ user + sys  → CPU 密集 → 优化算法/向量化/访存
real ≫ user + sys  → I/O 等待 → 减 IO / 异步 / 批处理
sys 占比高          → 频繁系统调用 → 批量 IO、减少调用次数
user 占比高          → 主要在做计算
```

> 👉 **性能分析主要盯 `user`**：`real` 受负载影响会抖，不适合做精确对比。

### 2. 极小耗时的测量：`rdtsc`

x86 内建时间戳计数器，每周期 +1。适合 `time` 都测不出的代码段。

```c
asm volatile("rdtsc" : "=a"(lo), "=d"(hi));
cycles = ((unsigned long long)hi << 32) | lo;
```

- 换算时间：`cycles / 主频`（3 GHz → 1 周期 ≈ 0.33ns）
- ⚠️ 现代 CPU 乱序会打乱计时，可配合 `lfence`/`cpuid` 做序列化屏障
- 多次取平均抑制调度抖动
- 示例代码：[`basis/Measure/rdtsc.c`](../../basis/Measure/rdtsc.c)（该文件有 `k` 未初始化的**测量污染**，见 `30 测量纪律手册`）

### 3. 两个效率指标（对接 Roofline 两根轴）

$$计算效率 = \frac{实测\ GFLOPS}{理论峰值\ GFLOPS},\qquad 访存效率 = \frac{有效\ GB/s}{理论\ GB/s}$$

- 计算效率低 → 流水线停顿/分支预测错/向量化不足
- 访存效率低 → 缓存命中差/访问不连续/预取不够

### 4. 延迟 vs 吞吐

不是简单此消彼长：**批处理可做到"高吞吐 + 高延迟"**（流水线），单请求优化追求**低延迟**。

### 5. 加速比（优化效果的记分牌）

$$speedup = \frac{优化前执行时间}{优化后执行时间}$$

本仓库 `TMA/` 每个实验的加速比就是这么算的（`false_sharing_1` 15.8x、`warmup` 70x）。

### 6. Amdahl 定律：**串行部分是硬天花板**（固定问题规模）

$$S = \frac{1}{(1-p) + p/S_p},\qquad S_p\to\infty \Rightarrow S_{max} = \frac{1}{1-p}$$

- p = 可加速部分占比
- **实践含义**：先优化占比最大的**热点**，冷门路径抠得再狠也白搭
- 这也是所有工具先做**热点分析**的原因

### 7. Gustafson 定律：**问题能摊大**（扩展问题规模）

$$S(n) = (1-\alpha) + \alpha \cdot n$$

加处理器的同时把问题也做大 → 串行部分被稀释。**超算/大数据的主场**。

| | Amdahl | Gustafson |
|--|--------|-----------|
| 规模 | 固定 | 随处理器扩 |
| 串行 | 硬顶 | 可被稀释 |
| 适合 | 延迟敏感 | 吞吐敏感 |

**实战顺序**：先 Amdahl 定位瓶颈 → 再 Gustafson 评估扩展潜力。

### 8. Roofline 模型：一图判"喂不饱 vs 算不过来"

$$性能 = \min(算力峰值,\ 算术强度 \times 内存带宽)$$

```
性能(GFLOPS)
  ^        ┌──────────── 计算天花板 (Peak Performance)
  |       /
  |      /  ← 斜率 = 内存带宽
  |     /
  |    / ●你的程序（算术强度、性能）
  |   /
  |  /  访存瓶颈区
  +─┴───────────────→ 算术强度 (FLOP/Byte)
     ↑拐点
```

- **拐点左边（Memory Bound）**：数据搬不动 → 优化缓存/布局/预取
- **拐点右边（Core Bound）**：算力不够 → SIMD/循环展开
- **算术强度 = 每从内存搬 1 字节能算几次**——是本体系最高频的抽象之一

## 二、关键命令 / 公式速查

```bash
# 三时间
time ./a.out
/usr/bin/time -v ./a.out         # 更详细 (最大 RSS 等)

# CPU 周期级测量 (见 rdtsc.c)

# 加速比
speedup = T_before / T_after

# 效率 (OpenMP 加速比扫描里用)
E = S / P

# Amdahl 上限
S_max = 1 / (1 - p)

# Roofline 拐点
AI_ridge = Peak_GFLOPS / Bandwidth_GBps
```

## 三、代码实战 · 本机实测

### 实验 ① 算法是最高杠杆（`basis/Algorithm/max_sum.cpp`）

**四算法同一结果、耗时差上百万倍**：

```bash
cd basis/Algorithm && clang++ -O1 max_sum.cpp -o max_sum && ./max_sum
```

n=10000 结果（μs）：

| 算法 | 复杂度 | n=10000 |
|------|--------|---------|
| 暴力 | O(n³) | 30,738,375 (≈30.7s) |
| 暴力优化 | O(n²) | 18,545 |
| 分治 | O(n log n) | 60 |
| **Kadane** | **O(n)** | **8 μs** |

**三条铁证**：
1. **Max Sum 四行完全一致（38792）** → 排除所有其他变量，纯算法杠杆。
2. **n 从 5000→10000 翻倍**：暴力耗时 **×8 = 2³**、暴力优化 **×4 = 2²**、Kadane ≈ ×2 → Big-O 不是理论，是**能跑出来的物理事实**。
3. **暴力→Kadane = 380 万倍**，`-O3`/`restrict`/向量化都填不平一层复杂度鸿沟。这就是**"先谈算法、再谈一切"**的量化依据。

> 附带彩蛋：Kadane n=1000 显示 0μs → 快到 `chrono` 分辨率之外 → 呼应 `rdtsc` 存在的原因。

## 四、一句话收口

> **性能优化的第一步不是"改代码"，是"定基线、判瓶颈、算杠杆"**：
> 用 `time` 分 CPU/IO 类型 → 用 Amdahl 定位热点占比 → 用 Roofline 分 Core/Memory → 用 Big-O 阶梯决定优先做算法还是做微操。

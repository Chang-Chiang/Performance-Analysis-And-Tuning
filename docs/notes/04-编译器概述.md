# 04 · 编译器概述

> **立意**：源码 ≠ 机器码。编译器是"自动优化厨师"——**`-O` 级别 = 授权它优化多少**。读懂它做了什么/没做什么，是**所有单核优化的前提**。

---

## 一、理论主干

### 1. 编译流程三段

```
源代码 → [前端: 词法→语法→语义→IR] → [中端: 目标无关优化] → [后端: 指令选择/寄存器分配/调度] → 汇编 → 链接 → 可执行文件
```

**LLVM 特色**：多前端（Clang / Flang / rustc / Swift）→ 统一到 **LLVM IR**（SSA 形式）→ 中端一串 Pass → 多后端（x86/ARM/RISC-V…）。

**IR/SSA 一句话**：每个值只被赋值一次（`%add = add nsw i32 %0, %mul`）→ 数据流一目了然 → 编译器才能安全做 DCE / 常量传播 / 向量化。你不用会写，但要知道能 dump：
```bash
clang -emit-llvm -S file.c -o file.ll   # 看编译器眼中的你的代码
```

### 2. ⭐ 优化级别表（日常够用）

| 级别 | 干什么 | 何时用 |
|------|--------|--------|
| `-O0` | 完全不优化，忠实照搬源码 | **调试**（变量可观察）|
| `-O1` | 基础优化（instcombine/simplifycfg/loops/unroll）| 兼顾编译速度 |
| `-O2` | **+ 内联 + 自动向量化** (`-fvectorize`/`-fslp-vectorize`) | **默认档 / 性能分析用** |
| `-O3` | + 激进内联、更深展开、跨函数优化 | 性能敏感生产环境 |
| `-Ofast` | -O3 + **`-ffast-math` 等浮点放开** | 只在验证精度可接受后用 |
| `-march=native` | 让编译器针对本机 CPU 生成 AVX2/FMA 等 | 单机部署首选 |

> **铁律**：**性能分析必须开 `-O2/3`**（用 `-O0` 分析瓶颈是假的）；再加 `-g` 让工具能定位到源码行。

### 3. 中端主力招式（认识这些名词，第 5-7 课反复出现）

| 招式 | 作用 | 开关 | 关联 |
|------|------|------|------|
| **死代码删除 DCE** | 删算了也没人用的代码 | `opt -dse` | `basis/Intraprocedural/dce.cpp` |
| **函数内联 Inline** | 小函数嵌入调用处，省调用开销 | `-Rpass=inline` | `function_inlining_1` 实验 |
| **循环级向量化** ⭐ | 一次处理 4/8 个数据 | `-fvectorize`（-O2 默认）| `vectorization_1/2` |
| **SLP 基本块向量化** | 块内同构指令打包成向量 | `-fslp-vectorize` | `basic_block_vectorization.cpp` |
| **循环展开 Unroll** | 复制循环体，减跳转、增调度空间 | `-funroll-loops` | 代价：寄存器压力 |
| **循环剥离 Peel** | 头几次"不对齐"迭代单独处理 | `-mllvm -unroll-peel-count` | 让主循环满足对齐 |
| **循环分布 Distribute** | 把含依赖的语句拆出去，其余可向量化 | `-mllvm -enable-loop-distribute` | |
| **浮点放开 fast-math** | 允许重排加法/除转乘等，解锁向量归约 | `-ffast-math` | 精度换性能 |
| **数据预取** | 提前搬数据进缓存 | `__builtin_prefetch(addr,rw,loc)` | `swmem_prefetch_1` |

> 👉 有个规律：**很多循环优化的最终目的，是"给向量化扫清障碍"**（剥离、分布、展开都服务于让 `-fvectorize` 生效）。

### 4. ⭐ 最实用技能：让编译器"交代"它做了什么

**别猜，直接问编译器**——这是第 4 课最应立刻上手的招式：

```bash
# clang: 看哪些循环成功向量化 / 失败原因 / 内联决策
clang -O2 -Rpass=loop-vectorize         app.c   # 成功
clang -O2 -Rpass-missed=loop-vectorize  app.c   # 失败 + 原因
clang -O2 -Rpass=inline                 app.c   # 内联决策

# gcc: 对应
gcc -O2 -fopt-info-vec-optimized app.c
gcc -O2 -fopt-info-vec-missed    app.c
```

**报告怎么读**：
- `vectorized loop (vectorization width: 8, interleaved count: 4)`
  - **width 4/8** = 向量宽度（4×float=128 位 SSE / 8×float=256 位 AVX2）
  - **interleaved count** = 交错迭代数，为短向量填充流水线
- `loop not vectorized: cannot prove it is safe to mutate memory` → **指针别名问题**，加 `restrict` 解锁

### 5. LTO（链接时优化）

普通编译每个 `.c` 单独编译成 `.o`，编译器看不到别的文件 → 跨文件没法内联/删死代码。
**LTO = 把优化推迟到链接阶段**，所有模块 IR 汇合，编译器获得"全局视野"。

| 模式 | 特点 |
|------|------|
| `-flto=full` | 合并所有 IR 成一个大模块统一优化，**更彻底但链接慢** |
| `-flto=thin` | 模块独立按需导入，**链接快，适合大工程/增量编译** |

`TMA/misc/lto/` 实测 **1.5x** 加速。

### 6. 数学库（简提）

- **BLAS**：Level 1 向量-向量 / 2 矩阵-向量 / 3 矩阵-矩阵
- **MKL**：Intel 官方版；命名 `dgemm` = **d**ouble + **ge**neral + matrix **m**ultiply
- 直接调 `cblas_dgemm` 通常远快于自己写三重循环

## 二、关键命令速查

```bash
# 三段编译产物
clang -E file.c -o file.i      # 预处理
clang -S file.c  -o file.s     # 汇编
clang -c file.c  -o file.o     # 目标文件
clang file.o -o app            # 链接

# 看 IR / AST / Tokens
clang -emit-llvm -S file.c -o file.ll
clang -fsyntax-only -Xclang -ast-dump file.c

# 优化 + 向量化报告
clang -O2 -Rpass=loop-vectorize -Rpass-missed=loop-vectorize file.c

# 反汇编确认 SIMD
clang -O2 -mavx2 file.c -S -o file.s
grep -E 'ymm|vmovaps|vmulps' file.s
```

## 三、代码实战 · 本机实测

### 实验 ③ `-O0 vs -O2`（同一份代码，编译器帮你免费提速 ~5x）

`basis/Measure/loop_unrolling_before.c`（N=10⁷ int 数组运算）：

| 级别 | 程序自计时 | user | sys | real |
|------|-----------|------|-----|------|
| `-O0` | 0.0325 s | 0.049 s | 0.034 s | 0.083 s |
| `-O2` | **0.0062 s** | 0.012 s | 0.032 s | 0.044 s |

- **一个字没改，仅 `-O0 → -O2` 就快 5.2x**。这就是"编译器是自动优化厨师"、`-fvectorize`/LICM/内联 的合力。
- `sys` 高达 0.03s = **120MB 全局数组首触发的缺页中断**（对应第 7/9 课 first-touch 讨论的 CPU 版）。
- `rdtsc.c` 里的 **`k` 是未初始化局部变量** → 测量污染，见 `30 测量纪律手册`。

### 实验 ④ 让编译器"交代"向量化 + 手写 intrinsics 的宽度锁定

`basis/ILP/loop_vectorization.cpp`（SSE intrinsics 例子）：

```bash
clang++ -O2 -Rpass=loop-vectorize -Rpass-missed=loop-vectorize -c loop_vectorization.cpp
# remark: vectorized loop (vectorization width: 4, interleaved count: 2)
```
→ 编译器坦白：它把标量循环改成 **width=4（128 位 SSE）** 的向量循环。

**SSE vs AVX2 反汇编对比**（本机 AVX2 可用）：

| 编译 | `loop_vectorization.cpp`（写死 `__m128`）| 纯标量 int 数组循环 |
|------|---------------------------------------|-------------------|
| `-msse2` | 68 xmm 指令 | 37 xmm |
| `-mavx2` | **0 ymm** ⚠️ | **17 ymm** ✅ |

👉 **最有价值的结论**：**源码里手写 `__m128` 会把向量宽度锁死到 128 位**，`-mavx2` 也撑不大；而**"干净的连续标量循环 + `-O3 -march=native`"** 让自动向量化器主动升到 256 位 ymm（一次 8 个 int）。

> **现代优化 80% 靠编译器**——把代码写成"可被优化形状"（连续、`restrict`、消依赖）比手写窄版本 intrinsics 更快、更可移植。手写只在特殊模式（gather/scatter/位操作，如 `compiler_intrinsics_2` 找换行符 15.1x）才值得。

## 四、一句话收口

> **优化开关 `-O2` 是性能分析的最低门槛**；`-Rpass-missed=loop-vectorize` 是你排查"循环没变快"的第一招；**能让编译器做的，就别自己锁死**。

# 07 · 访存优化

> **立意**：第 1 课 Roofline 反复提醒——**多数程序其实是"喂不饱"（Memory Bound）**。这一课按存储层次（寄存器→缓存→内存→磁盘）分层拆解，所有 `memory_bound` 实验的根基。

---

## 一、⭐ 根因：存储层次（一切访存优化的物理起点）

CPU 取料的"距离"分 5 档：

```
手边调料(寄存器)      <1ns     几百字节
灶台旁(L1)            1-2ns    32-64KB
储物柜(L2/L3)         3-20ns   几百KB~几十MB
小区仓库(主存 DRAM)   50-100ns 几GB
远程总仓(磁盘)        ms级      TB
```

**震撼数字**：**寄存器 <1ns vs 主存 50-100ns，差近 100 倍**——CPU 算一条指令 1ns，但等主存取数据 100ns，**99% 时间在干等**。这就是 **Roofline "访存瓶颈区"的物理来源**。

**两条铁律**：
- 优化优先级 **寄存器 > 缓存 > 内存 > 磁盘**——越靠近 CPU 收益越大
- 一切手法都在提高**数据局部性**：让"马上要用的数据"待在"离 CPU 最近的地方"

---

## 二、寄存器优化（离 CPU 最近，先榨干）

`basis/Memory/RegisterOptimization/`

| 手法 | 干什么 | 文件 |
|------|--------|------|
| **减少全局变量** | 全局变量**独占寄存器**，改局部 | `register_allocation.c` |
| **标量替换** | `a[i]` 用两次？先 `x=a[i]` 装进寄存器 | `scalar_replacement_*.c` |
| **减少内存写** ⭐ | 累加在寄存器做，**最后写一次** | `scalar_replacement_accumulation.c` |
| **寄存器重用** | 展开后同一数据留寄存器复用（连 06）| `loop_unroll_register_reuse.c` |

⚠️ **过犹不及——寄存器溢出(spill)**：活跃变量太多 > 寄存器数 → 甩到栈上（额外 LOAD/STORE）反而变慢。控制单函数局部变量数、拆多函数。

## 三、缓存优化（本课最实战，治 Memory Bound）

**核心事实**：缓存以 **缓存行 64 字节** 为单位搬运。访问 1 个 `int`，硬件把整个 64B(16 个 int) 一起搬进来——**这就是"连续访问快、跳步访问慢"的底层原因**（第 5 课循环交换的物理学解释、第 6 课实验⑤实测印证）。

### 1. 缓存分块 Tiling ⭐（`loop_tiling_1` 1.75x）
把大矩阵切成**能塞进缓存的小块**，一块算完才换下一块。

**分块公式**（双精度矩阵乘，务必背）：
$$3 \times S^2 \times 8 \le C \implies S \le \sqrt{C/24}$$
（3 个矩阵块 × 8 字节 × 需塞进容量 C 的缓存）。工程实测最优 ~128。

### 2. 数组分类与缓存映射（进阶）
按"行长 × 元素大小"是否 **64B 整数倍 / 恰好=缓存组数整数倍**分三档。坑在第三类：行长正好是缓存大小整数倍 → 列数据全挤进同一缓存组 → 疯狂冲突。
> **朴素解法**：251×251 补零扩成 256×256（避开 2 的幂次冲突），实测 1.6x。

### 3. ⭐ 减少伪共享（False Sharing）
多核各写 `sum[i]`，但 `sum[0..7]` 挤在**同一 64B 缓存行** → 一个核写触发 MESI 一致性 → **别核的这行失效** → 反复争抢，并行反而巨慢。

**三味药**（详见 `08 § 三 实验⑥` 实测）：
- `alignas(64)` 让每变量独占一行
- 局部变量累加、最后写回一次
- OpenMP `reduction` 私有化（**首选**：既消争用又能向量化）

**分析工具**：**`perf c2c`**（专查缓存行争用）。

### 4. 数据预取 Prefetch（`swmem_prefetch_1` 3.1x）
```c
__builtin_prefetch(addr, rw, locality);   // rw:0读/1写; locality:0一次性~3高复用
```
> **铁律**：**顺序访问硬件预取器已够用**，别手动预取。软件预取只在**访问可预测但不连续**（链表、稀疏矩阵、哈希表）时才值得——那种模式硬件猜不到。

## 四、内存优化（DRAM 这一层）

`basis/Memory/MemoryOptimization/`

- **减少内存读写**：中间结果存寄存器/临时变量 → `reduce_memory_access.c`
- **数据对齐**：地址是元素大小整数倍时最高效；未对齐要多访存 + 用不了向量指令 → `data_alignment.c`
- **结构体对齐**：成员**按大小降序排**减少填充
  ```c
  struct A1 { char a; int b; char c; short d; } // 12 字节(填充浪费)
  struct A2 { char a; char c; short d; int b; } // 8 字节(紧凑) ← 省的就是缓存
  ```
- **访存与计算重叠**：把 LOAD 塞在计算指令之间（编译器/乱序硬件自动做，你只要**别让循环太"稀疏"**）
- **DMA**：外设↔内存直传绕过 CPU

> 结构体压缩/对齐直接连到 `data_packing` 实验（40B→8B，排序 **7.5x**）——省内存 = 缓存装更多 = 少 miss。

---

## 五、磁盘优化（最慢层，顺序为王）

- **多线程读**：随机读可达单线程 **10x+**（但单请求响应时间变长）
- **避免随机写**：磁头换道 → 先在内存排序再顺序写
- **磁盘预读**：Linux 窗口倍增预读；大文件顺序读用 `posix_fadvise(fd, offset, len, POSIX_FADV_SEQUENTIAL)`

## 六、数据布局：AoS vs SoA + 转置（第 6 课也强调）

`basis/Memory/DataLayout/`

**数据转置**：内层按列访问(x[i][1] 跨行跳步) → 把数组转置让访问变连续 → `array_transposition.c`（换一种方式实现循环交换）。

**AoS vs SoA**：见 `06 § 三`；两者是"**在数据中找并行**"（第 5 课那句心法）的落地。
代码：`array_restructuring.c`（AoS 打包）、`struct_splitting.c`（按维度拆）、`struct_array_conversion.c`（转 SoA）。

## 七、把 TMA Memory Bound 子类对上药方（闭环！）

| TMA 子类 | 症状 | 本课药方 |
|---------|------|---------|
| **L1/L2/L3 Bound** | 数据没在对应缓存 | 循环交换 / 分块 / 转置 |
| **DRAM Bound** | 老跑主存取 | 紧凑布局、压缩类型、SoA（缓存装更多）|
| **TLB / 大工作集** | 地址翻译/容量 | 缓存分块、大页(第 3 课硬件)|
| **Store Bound / 伪共享** | 多核争缓存行 | `alignas(64)`、局部变量、`perf c2c` |
| **随机 / 跳步访存** | 硬件预取猜不到 | `__builtin_prefetch` |

## 八、代码实战 · 交叉引用（本机实测）

本课两大最直观的实测在**兄弟文档**里，一起看效果最好：

- **实验 ⑤ 循环交换 → IPC 从 0.68→6.04** → 详见 **`03 § 五`**（9.5x 加速、cache-ref 少 12x）
- **实验 ⑥ 伪共享 → 缓存行争用 + 测量纪律** → 详见 **`08 § 三`**（padding/reduction 治愈，噪声陷阱坐实）
- **实验 ⑧ AoS vs SoA → 带宽浪费 3x → 5.02x 慢** → 详见 **`06 § 五`**（"已向量化 ≠ 快"）
- **实验 ② 链表 pointer chasing → cache miss 灾难** → 详见 **`05 § 七`**（约 1.8 万倍）

> 这四个实验共同证明本课一句话：**"多数程序其实不是算不过来，是数据供不上。"**

## 九、一句话收口

> **优化顺序按存储层次：寄存器 > 缓存 > 内存 > 磁盘**。缓存这一层的四件重器是：**分块（S≤√(C/24)）、伪共享（alignas/perf c2c）、预取（只在可预测不连续时手动）**；再叠加**紧凑类型 + 结构体对齐 + AoS→SoA**——**让缓存装下更多 = 治 DRAM Bound**。

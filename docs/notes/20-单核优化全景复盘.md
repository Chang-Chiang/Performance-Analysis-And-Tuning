## 一、单核优化的「诊断 → 开药 → 验证」闭环

```
┌────────────────────────────────────────────────┐
│ ① 度量基线 (01)  time / -O2/3 编译, 记录 user 时间 │
└────────────────────────────────────────────────┘
                       ↓
┌────────────────────────────────────────────────┐
│ ② 定位热点 (02)  perf record + 火焰图 / VTune Hotspots │
└────────────────────────────────────────────────┘
                       ↓
┌────────────────────────────────────────────────┐
│ ③ 判瓶颈类型 (03 TMA)                            │
│   perf stat --topdown → -l2 → -l3 → perf record 落代码 │
└────────────────────────────────────────────────┘
     ↙ Bad Spec     ↓ Frontend      ↘ Backend
查表/分支优化    i-Cache/iTLB       ┌───────┴───────┐
                              Memory Bound    Core Bound
                                (喂不饱)       (算不过来)
                                    ↓             ↓
┌─────────────────────────┐ ┌─────────────────────────┐
│ ④-A 访存药箱 (05/07)     │ │ ④-B 算力药箱 (05/06)     │
│  循环交换 / 分块         │ │  SIMD 自动向量化         │
│  AoS→SoA · 紧凑类型      │ │  消依赖链 · ILP 展开     │
│  数据预取 (不连续才手动) │ │  FMA · restrict · 内联   │
│  alignas64 治伪共享      │ │  手写 intrinsics (备用)  │
└─────────────────────────┘ └─────────────────────────┘
                       ↘             ↙
┌────────────────────────────────────────────────┐
│ ⑤ 验证 (回①)  重测 user → 加速比 = 前/后        │
│  不达预期 → 说明瓶颈判断错或引入新瓶颈 → 回 ③    │
└────────────────────────────────────────────────┘
```

**闭环灵魂**：优化不是背手法，是**"先用 TMA 分诊，再开对应药"**。开错药（给 Memory Bound 上向量化）几乎无效——前面每课练习反复训练这个直觉。

## 二、两个药箱对照（最好背这张表）

| 维度 | 🔴 Memory Bound（喂不饱）| 🔵 Core Bound（算不过来）|
|------|----------------------|------------------------|
| TMA 特征 | IPC 低 + cache-miss 高 | IPC 尚可但执行单元饱和 / 依赖链长 |
| 根本矛盾 | 数据离 CPU 太远（存储层次 07）| 指令并行度/向量化不足（06）|
| 主力药 | 循环交换·分块、AoS→SoA、紧凑类型、预取、alignas | SIMD 向量化、消依赖链、ILP 展开、FMA、内联 |
| 05 对应手法 | 循环级"目的 A：局部性" | 循环级"目的 B：消依赖暴露并行"、语句级去相关 |
| 编译器配合 | 结构体对齐、-O2 布局 | -fvectorize、restrict、-ffast-math |
| 实测印证 | **实验⑤** 循环交换 IPC 0.68→6.04、9.5x | **实验⑧** SoA vs AoS 5x（带宽浪费 3×）|

## 三、贯穿暗线：编译器 vs 手写的分工（第 4 课埋的伏笔，第 5-7 课全在用）

```
你能做的                              编译器替你做的 (需你解锁)
─────────                            ─────────────────
把循环写成连续访问        ──喂料给──►  自动向量化 -fvectorize
加 restrict / 消别名      ──解锁──►    指针不重叠, 敢向量化
AoS→SoA / 紧凑结构体      ──解锁──►    对齐访存 + 向量加载
标量重命名去依赖          ──解锁──►    乱序调度 + 向量化
调 -O2/-O3/-ffast-math/LTO ──选档─►   优化激进程度
```

**关键认知**：**现代优化 80% 靠编译器，20% 靠你把代码改成"能优化"的形状**。检查工具永远是那句：
```bash
clang -O2 -Rpass-missed=loop-vectorize app.c   # 问编译器: 你为啥没帮我优化?
```

**"已向量化 ≠ 快"**（实验⑧铁证）：`-Rpass` 只报"用没用 SIMD"，报不了"访存多糟"。**必须 `-Rpass` + 计时/perf 双视角交叉验证**。

## 四、优化杠杆层级 × 全 16 实验加速比

**用数据坐实第 5 课"杠杆阶梯"**：

| 杠杆层级 | 实验 | 手法 | 加速比 |
|---------|------|------|--------|
| **算法**（最高）| `warmup` | O(N)→O(1) | **70x** 🔺 |
| **数据布局 / 访存** | `false_sharing_1` | alignas64 消伪共享 | 15.8x |
| | `loop_interchange_2` | 高斯模糊列→行 | 9.7x |
| | `data_packing` | 结构体压缩 40B→8B | 7.5x |
| | `loop_interchange_1` | 矩阵乘 i-j-k→i-k-j | 6.9x |
| | `swmem_prefetch_1` | 哈希表随机访问软件预取 | 3.1x |
| | `loop_tiling_1` | 矩阵转置缓存分块 | 1.75x |
| **打破依赖 / 向量化** | `vectorization_2` | uint16→uint32 断依赖链 | **20.9x** 🔺 |
| | `compiler_intrinsics_2` | AVX2 批量查找换行符 | 15.1x |
| | `dep_chains_1` | M 路并行链表查找 | 3.6x |
| | `vectorization_1` | AoS→SoA + 自动向量化 | 2.1x |
| | `compiler_intrinsics_1` | SSE4.1 前缀和 | 1.14x |
| **过程 / 编译** | `function_inlining_1` | qsort→std::sort+lambda | 1.63x |
| | `lto` | 跨翻译单元内联 | 1.50x |
| | `pgo` | Profile-Guided Opt | ~1x |
| **分支** | `lookup_tables_1` | 查找表替代分支链 | 1.87x |

**三个洞察**：
1. `warmup`(算法) 70x 和 `vectorization_2`(消依赖) 20.9x 是"顶级杠杆"的两个代表——**改对本质，一骑绝尘**。
2. 访存一族普遍高倍(3~16x) → 印证"**多数程序是 Memory Bound**"。
3. `compiler_intrinsics_1` 1.14x、`pgo` ~1x → **并非所有优化都划算**，用 Amdahl 权衡投入产出。

## 五、按 TMA 瓶颈归档实验（正确的索引法）

**别按"手法"记实验，按 TMA 瓶颈分类记**——这才是可迁移的诊断思维：

```
TMA 诊断结果         →  该看哪个实验 (技术)
────────────────────────────────────────────
Backend/Memory_Bound →  loop_interchange_1/2  (循环交换)
                       loop_tiling_1           (缓存分块)
                       data_packing            (数据压缩 / AoS-SoA)
                       swmem_prefetch_1        (软件预取)
                       false_sharing_1         (伪共享 alignas)
Backend/Core_Bound   →  vectorization_1/2      (向量化 + 消依赖)
                       compiler_intrinsics_1/2 (手写 SIMD)
                       dep_chains_1            (打破依赖链)
                       function_inlining_1     (内联)
Bad_Speculation      →  lookup_tables_1        (分支转查表)
(编译/流程层面)      →  lto / pgo / warmup
```

## 七、复盘收口（三句话）

1. **闭环五步**：度量 → 热点 → TMA 分类 → 开药 → 回测；**开药前先分类**，别乱补。
2. **两大药箱**：Memory Bound 靠"把数据搬近+摆对"（07），Core Bound 靠"暴露并行+向量化"（06），而**编译器是共同执行者**，你负责"把代码改成可优化形状"（04）。
3. **杠杆有高低**：算法 > 布局 > 局部性 > 向量化 > 编译开关——但一切都要用**加速比 + 实测**说话。

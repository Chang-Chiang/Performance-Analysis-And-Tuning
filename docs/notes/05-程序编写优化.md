# 05 · 程序编写优化

> **立意**：前 4 课是"用工具/靠编译器"。这一课回归本质：**在你动手写代码的那一层，怎么写出天生就快的程序**。粒度分 5 层：**算法 → 数据结构 → 过程 → 循环 → 语句**。

---

## 一、⭐ 核心心智：五层优化杠杆

**每层的典型收益**（决定你该把精力放哪）：

```
算法复杂度  ………  10x ~ 1,000,000x   ← 先查这里
数据结构/布局 ….   2x ~ 10x          （AoS→SoA、类型压缩、结构对齐）
缓存/局部性 ….     1.5x ~ 10x         （循环交换/分块/转置）
向量化(SIMD) ….    2x ~ 4x            （一条指令算 4/8 个）
编译器/链接 ….     1.1x ~ 1.5x        （-O3、LTO）
```

**本仓库 `TMA/` 各实验加速比恰好印证**：
`warmup`（算法）70x ≫ `false_sharing_1`（并行/缓存）15.8x ≫ `vectorization_1`（向量化）2.1x ≫ `lto`（编译）1.5x。

> 灵魂一句话（工程总结原话）：**"从 O(n³) 到 O(n) 的算法优化，带来的提升远超编译器优化或硬件升级。"**

## 二、算法优化（最高杠杆）

### 2.1 复杂度量级直觉
`O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)`

### 2.2 经典案例：最大连续子向量和（4 种算法）

| 方法 | 复杂度 | 思路 |
|------|--------|------|
| 暴力枚举 | O(n³) | 三重循环每个子向量重头求和 |
| 枚举优化 | O(n²) | 累加变量复用，砍掉最内层 |
| 分治 | O(n log n) | 左右+跨中点递归 |
| **Kadane (DP)** | **O(n)** | `f[i]=max(f[i-1]+x[i], x[i])`，扫一遍 |

→ 代码：[`basis/Algorithm/max_sum.cpp`](../../basis/Algorithm/max_sum.cpp)；实测数据（本机 n=10000 差 **380 万倍**）详见 **`01 § 三 实验 ①`**。

### 2.3 排序：常数级别的讲究
`sort.cpp` — 冒泡/插入/选择都是 O(n²) 但常数差异大；实践中 std::sort/introsort/parallel sort 才是选择。

## 三、数据结构优化：选对结构 + 选对类型 + 摆对布局

### 3.1 选对结构 → 数量级差
| 结构 | 查找 | 插入 | 删除 | 备注 |
|------|------|------|------|------|
| 数组 | O(N) | O(1) 尾 | O(N) | 缓存友好 |
| 有序数组 | O(log N) | O(N) | O(N) | 二分 |
| 链表 | O(N) | O(1) | O(N) | **指针追逐 → cache miss 灾难** |
| 平衡树 | O(log N) | O(log N) | O(log N) | 通用 |
| 哈希表 | **O(1)** | O(1) | O(1) | 无关键字访问慢 |

**代码**：[`basis/DataStructure/search.cpp`](../../basis/DataStructure/search.cpp) — 数组二分 vs 链表顺序，两条独立杠杆（复杂度 × 缓存友好性）**叠乘**。

### 3.2 选更小的数据类型（精度允许下）

| 场景 | short vs int | float vs double |
|------|-------------|-----------------|
| SSE 加法 | **快约 2x**（同宽塞 2 倍元素） | |
| 256×256 矩阵乘 | | 单精度 **1.88x** |

**紧凑类型 = SIMD 更宽 + 缓存装更多**。位域/`float32`/`uint16` 直接连到 `data_packing` 实验（40B→8B，排序 **7.5x**）。

### 3.3 稀疏矩阵存储格式（决定访存效率）
`basis/DataStructure/spmv.cpp` 对比 **COO / CSR（最常用）/ DIA / ELLPACK**。通用 CSR、对角线 DIA、GPU 均匀分布 ELLPACK、动态构建 COO。

### 3.4 AoS vs SoA 一句话总纲（**本课最高频**，详见 06/07）

```
AoS  [{x,y,z},{x,y,z},...]   同一元素的属性挨着 → 批量取 x 时跨结构体跳步 → 向量化差
SoA  [x,x,...][y,y,...][z,z,..] 同一属性元素挨着 → 一条 load 拉 8 个 x  → 向量化友好
```

## 四、过程级优化：函数之间怎么传、怎么调

`basis/Intraprocedural/`

| 手法 | 干什么 | 关键点 |
|------|--------|--------|
| **`restrict` 消别名** ⭐ | 告诉编译器"两指针不重叠"，**解锁向量化** | 与第 4 课 `-Rpass-missed` 直接呼应 |
| **常数传播** | 提前算死的表达式手动算成常量 | 编译器未必能识别复杂控制流 |
| **传参优化** | 参数 ≤4、大结构体传指针、`const` 修饰 | 避免寄存器溢出到栈 |
| **内联** | 小函数体展开到调用处 | 呼应 `function_inlining_1` |
| **过程克隆** | 一个函数生成多版本，按上下文选用 | 让每版本针对特定 j=0/j>4 优化 |
| **全局变量 → 参数** | 全局变量独占寄存器 + 阻碍并行 | 尽量局部化 |

**代码**：[`alias.c`](../../basis/Intraprocedural/alias.c)、[`constant.cpp`](../../basis/Intraprocedural/constant.cpp)、[`param_passing.cpp`](../../basis/Intraprocedural/param_passing.cpp)、[`inline.cpp`](../../basis/Intraprocedural/inline.cpp)

## 五、循环级优化：⚙️ 手法最多，但只有两个目的

**记住这张归类表**（10 种变换 → 2 大目标，直接对应 TMA 瓶颈）：

### 目的 A：**提升数据局部性**（治 Memory Bound）
| 手法 | 一句话 | 文件 | 实验印证 |
|------|--------|------|---------|
| **循环交换 Interchange** | 让**最内层沿连续方向**走 | [`permutation.cpp`](../../basis/Loop/permutation.cpp) | `loop_interchange_1` 6.9x、`_2` 9.7x |
| **循环分块 Tiling** | 把工作集切成能塞进缓存的小块 | [`block.cpp`](../../basis/Loop/block.cpp) | `loop_tiling_1` 1.75x |

### 目的 B：**打破依赖，暴露并行**（治 Core Bound）
| 手法 | 一句话 | 文件 |
|------|--------|------|
| 不变量外提 LICM | 循环不变计算移到外面 | [`invariant.cpp`](../../basis/Loop/invariant.cpp) |
| 循环展开 Unroll | 复制循环体增调度空间（**代价：寄存器压力↑**）| [`unroll.cpp`](../../basis/Loop/unroll.cpp) |
| 循环分布 Distribute | 把有依赖的语句拆出去，剩余可向量化 | [`distribution.cpp`](../../basis/Loop/distribution.cpp) |
| 循环合并/压紧 | 多循环并一个，省迭代开销 | [`merge.cpp`](../../basis/Loop/merge.cpp) / [`compaction.cpp`](../../basis/Loop/compaction.cpp) |
| 循环分段 Segment | 单层→多层，外层并行内层向量化 | [`segment.cpp`](../../basis/Loop/segment.cpp) |
| 循环分裂 Splitting | 拆迭代段，处理边界 | [`splitting.cpp`](../../basis/Loop/splitting.cpp) |
| 循环倾斜 Tilting | 仿射变换处理三角依赖 | [`tilting.cpp`](../../basis/Loop/tilting.cpp) |

> **循环交换的精髓**（务必内化）：
> ```c
> // ✅ 内层遍历 j（同一行连续）→ 缓存友好
> for (i) for (j) A[i][j] = ...;
> // ❌ 内层遍历 i（跨行跳步 stride）→ 疯狂 cache miss
> for (j) for (i) A[i][j] = ...;
> ```

**分块大小公式**（背下来，实战直接用）：双精度矩阵乘
$$3 \times S^2 \times 8 \le C \implies S \le \sqrt{C/24}$$

## 六、语句级优化：最细粒度

`basis/Statement/`

| 手法 | 干什么 | 服务谁 |
|------|--------|--------|
| **DCE** 删冗余 | 死代码/未用变量 | 通用 |
| **代数变换** | `(a+a)+(6*a)/2` → `5*a` | 减少运算 |
| **CSE** 公共子表达式 | `a+b` 三处 → 存 tmp 一次 | 通用 |
| **去除相关性**：标量扩展 / **标量重命名** / 数组重命名 | 打破循环迭代间依赖 | ⭐ **服务向量化** |
| **合并判断条件 / 选择指令 `? :` / 条件编译** | 减少分支跳转 | 治 Bad Speculation |
| **查表替代分支链** ⭐ | `if score>=90 'A' else if...` → `s[score/10]` | 呼应 `lookup_tables_1` 1.87x |
| **平衡判断树** | 线性 if-else 变平衡树，比较次数 6→4 | 同上 |

**代码**：[`dependency_scalar_rename.cpp`](../../basis/Statement/dependency_scalar_rename.cpp)、[`dependency_array_rename.cpp`](../../basis/Statement/dependency_array_rename.cpp)、[`select_optimization.cpp`](../../basis/Statement/select_optimization.cpp)

> 呼应第 3 课：**Bad Speculation** → 分支优化（查表）；**Core Bound** → 去除相关性；**Memory Bound** → 循环交换/分块。**五层优化和 TMA 瓶颈完全对得上号**。

## 七、代码实战 · 本机实测

### 实验 ② 数据结构杠杆（`basis/DataStructure/search.cpp`）

10⁷ 个元素、都查找**最后一个**（两者最坏情况）：

| 方式 | 数据结构 | 复杂度 | 实测 |
|------|---------|--------|------|
| 二分查找 | 有序数组 | O(log n) | **0.000001 s** |
| 顺序查找 | 链表 | O(n) | 0.018829 s |

**≈ 1.8 万倍差距**，源于**两重独立杠杆叠加**：

1. **算法本身**：二分 ≈ 24 步（log₂ 10⁷）vs 顺序 10⁷ 步 → 步数差约 40 万倍
2. **数据结构内存布局**（第 7 课预演）：
   - 数组**连续存储** → 硬件预取高效、缓存行利用率高
   - 链表**节点散落堆中**（每个 `malloc` 独立） → `p=p->next` 是指针追逐(pointer chasing)，每跳都可能 cache miss，**硬件预取猜不到下一节点地址**

> 👉 **数据结构的选择同时决定"算法复杂度上限"和"缓存友好性"**——两重收益叠乘。这就是第 5 课把"数据结构"放在仅次于"算法"的高杠杆位。

⚠️ 诚实提示：工程文档写"约 400 倍"是不同测试条件（平均情况、更小 n、不同机器）。**加速比会随机器/输入而变，基线要固定**（第 1 课）。

## 八、一句话收口

> **五层粒度：算法 > 数据结构 > 过程 > 循环 > 语句**。循环优化只有两个目的——**局部性（治 Memory Bound）+ 消依赖暴露并行（治 Core Bound）**；两个必记手法是 **`restrict` 解锁向量化** 和 **查表替代分支链**；一切服从那句心法：**"在数据中找并行性，而不是在代码中。"**

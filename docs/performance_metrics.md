## 1. 执行时间

- bash 命令获取

    ```shell
    $ time ./a.out
    real    0m0.003s
    user    0m0.001s
    sys     0m0.001s
    ```

    - **real (真实时间)**：从命令开始执行到结束所经历的墙上时钟时间（Wall Clock Time）。包括 CPU 执行时间、等待 I/O 时间、进程调度等待时间等。如果程序在等待磁盘 I/O 或网络响应，real 时间会明显大于 user + sys 时间。

    - **user (用户态时间)**：进程在用户空间执行代码所消耗的 CPU 时间。即程序本身逻辑运算（如计算、循环、函数调用等）所花费的时间，不包括内核代为执行的时间。

    - **sys (内核态时间)**：进程在内核空间执行系统调用所消耗的 CPU 时间。当程序调用如 `read()`、`write()`、`mmap()` 等系统调用时，CPU 需要切换到内核态来完成操作，这部分时间计入 sys。

    **分析要点：**

    - `real ≈ user + sys`：程序是 CPU 密集型，几乎没有等待
    - `real >> user + sys`：程序存在大量 I/O 等待或被其他进程抢占 CPU
    - `sys` 占比高：程序频繁进行系统调用（大量文件/网络 I/O）
    - `user` 占比高：程序主要在进行计算

    **性能分析主要关注 `user` 时间**：`user` 反映的是程序自身计算逻辑的 CPU 消耗，是优化代码算法和计算效率的直接目标。`sys` 时间通常由系统调用决定，优化空间在于减少调用次数（如批量 I/O）；`real` 时间受系统负载影响，不稳定，不适合用于精确的性能对比。

## 6. Amdahl 定律：重点优化热点

$S = \frac{1}{(1-p) + \frac{p}{S_p}}$

其中：
- $S$: 理论加速比
- $p$: 可并行化部分占总执行时间的比例
- $S_p$: 并行部分的加速比

**推导过程：**

1. 设程序总执行时间为 $T_{total}$

2. 程序分为两部分：
   - 串行部分：占总时间的 $(1-p)$，耗时 $(1-p) \cdot T_{total}$
   - 可并行部分：占总时间的 $p$，耗时 $p \cdot T_{total}$

3. 对可并行部分施加加速比 $S_p$ 后，该部分耗时变为：
   $T_{parallel} = \frac{p \cdot T_{total}}{S_p}$

4. 优化后的总执行时间：
   $T_{new} = (1-p) \cdot T_{total} + \frac{p \cdot T_{total}}{S_p}$
   $T_{new} = T_{total} \left[ (1-p) + \frac{p}{S_p} \right]$

5. 整体加速比：
   $S = \frac{T_{total}}{T_{new}} = \frac{1}{(1-p) + \frac{p}{S_p}}$

**极限情况：**

- 当 $S_p \to \infty$（并行部分完全加速），$S_{max} = \frac{1}{1-p}$
- 当 $p = 0.5$ 时，无论并行部分加速多少倍，最大加速比仅为 $2$
- 当 $p = 0.9$ 时，最大加速比为 $10$

## 7. Gustafson 定律：

$S(n) = (1 - \alpha) + \alpha \cdot n$

其中：
- $S(n)$: 扩展加速比
- $n$: 处理器数量
- $\alpha$: 可并行化部分占总工作量的比例

**推导过程：**

1. 设总工作量为 $W$，其中：
   - 串行部分：$(1-\alpha) \cdot W$
   - 可并行部分：$\alpha \cdot W$

2. 使用 $n$ 个处理器时，假设问题规模随处理器数量线性扩展：
   - 串行部分耗时不变：$(1-\alpha) \cdot W$
   - 并行部分耗时：$\frac{\alpha \cdot W}{n}$

3. 但 Gustafson 定律的关键假设是：**增加处理器时，问题规模也随之增大**

4. 当使用 $n$ 个处理器时，总工作量扩展为 $W' = W \cdot n$
   - 串行部分：$(1-\alpha) \cdot W'$
   - 并行部分：$\alpha \cdot W'$

5. 实际执行时间（以单处理器为基准）：
   $T_{serial} = (1-\alpha) \cdot W'$
   $T_{parallel} = \frac{\alpha \cdot W'}{n}$

6. 加速比：
   $S(n) = \frac{T_{serial} + T_{parallel}}{T_{serial}} = \frac{(1-\alpha) \cdot W' + \frac{\alpha \cdot W'}{n}}{(1-\alpha) \cdot W'}$
   $S(n) = (1-\alpha) + \alpha \cdot n$

**与 Amdahl 定律的区别：**

| 维度     | Amdahl 定律      | Gustafson 定律     |
| -------- | ---------------- | ------------------ |
| 问题规模 | 固定             | 随处理器扩展       |
| 关注点   | 固定问题的加速比 | 扩展问题的处理能力 |
| 串行部分 | 硬上限           | 可被"稀释"         |
| 适用场景 | 延迟敏感型任务   | 吞吐量敏感型任务   |

**指导意义：**

1. **串行部分不是绝对瓶颈**：当问题规模增大时，串行部分占比被"稀释"，加速比可以接近线性

2. **扩展性视角**：与其优化固定问题，不如考虑如何利用更多处理器处理更大规模的问题

3. **实际应用**：科学计算、大数据处理等领域，增加处理器往往意味着能处理更大的问题，而非仅仅加速原有问题

> 上面两个定律太偏理论了
> 个人总结，
> Amdahl 定律指导，重点优化热点耗时； 但同时又在说耗时受限于串行部分
> Gustafson 定律指导，优化可并行计算部分可增大计算规模
> 个人感觉，了解一下 Amdahl 定律就好了

## 附录：Roofline 模型

Roofline 模型是一种直观的性能分析工具，用于判断程序是计算密集型还是访存密集型，并预测性能瓶颈。

**核心概念：**

- **算力峰值 (Peak Performance)**：硬件理论最大计算能力，单位通常为 GFLOPS
- **访存带宽 (Memory Bandwidth)**：硬件理论最大内存带宽，单位通常为 GB/s
- **算术强度 (Arithmetic Intensity)**：程序中浮点运算次数与内存访问字节数之比，单位为 FLOPS/Byte

**模型公式：**

$$
Achievable Performance = \min(Peak Performance, Arithmetic Intensity \times Memory Bandwidth)
$$

**图形表示：**

```
Performance
(GFLOPS)
    ^
    |         _______________  ← 计算上限 (Peak Performance)
    |        /
    |       /
    |      /
    |     /
    |    /  ← 斜率 = 内存带宽
    |   /
    |  /
    | /
    |/________________________> Arithmetic Intensity (FLOPS/Byte)
```

**分析方法：**

- **计算瓶颈区 (Compute Bound)**：算术强度高于拐点时，性能受限于计算能力
- **访存瓶颈区 (Memory Bound)**：算术强度低于拐点时，性能受限于内存带宽
- **拐点 (Ridge Point)**：计算上限与访存上限的交点，算术强度 = Peak Performance / Memory Bandwidth

**优化策略：**

- 处于**访存瓶颈区**：优化数据访问模式，提高缓存命中率，减少内存访问
- 处于**计算瓶颈区**：优化计算算法，使用 SIMD 向量化，提高计算效率
